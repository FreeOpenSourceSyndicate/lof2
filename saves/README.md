# saves/ — owner-supplied save games (content-addressed)

This directory holds the save games the owner provides for testing, plus the
fixtures the test suite depends on.  Per `docs/RULES.md` **Rule 12**, a save the
user created with the game is **not proprietary** — it is part of this project —
so these files are committed.  Some of them are also the **only copy** (they are
not in the Internet Archive release), and the tests read them directly.

## Why not just `GAME1`, `GAME4`, … at the repo root?

The engine addresses saves by *slot*: `GAMES\GAME<n>`.  If owner uploads are
stored under slot names, a new upload for a slot that already has a file
silently overwrites it — which is exactly what happened to `GAME4` once.  Slots
are an engine concept, not an archival identity.  So uploads are **never** kept
under a slot name here.

## The scheme

Every save is filed under a **content-addressed** name:

```
<map>-<party-lead>-<md5[0:8]>.sav
```

* `<map>` — the dungeon/wilderness id from the save's location bytes
  (`DNG05`, `DNG00`, …).
* `<party-lead>` — the first present party member's name.
* `<md5[0:8]>` — the first 8 hex digits of the file's md5.

Because the hash is part of the name, two saves that differ by even one byte get
different filenames, and identical bytes always map to the same name.  **Nothing
is ever overwritten or deleted.**

`tools/ingest-save.sh` files uploads and regenerates `manifest.tsv` (a derived
table of what is here — the files themselves are the source of truth).

## How to add a save

1. Drop the file into `saves/inbox/` (or at the repo root as `GAME<n>`).
2. Run `tools/ingest-save.sh` (or just `./bootstrap.sh`, which calls it).

What happens:

| case | result |
|------|--------|
| bytes already archived (same md5) | skipped, no duplicate created |
| new save, name collides with a different save | filed under its md5 suffix, old file untouched |
| file is not a Legend of Faerghail save | rejected, nothing written |

Then, to play a specific archived save, copy it into a slot:

```sh
cp saves/dng00-Conan-d8b1cad7.sav game/GAMES/GAME4
```

`bootstrap.sh` does this automatically for the three well-known fixtures (slots
1, 4, 5); the slot copies are convenience only — tests read the archived files
directly, so a slot may hold whatever you last uploaded.

## Current fixtures

See `manifest.tsv` for the authoritative list.  The ones tests depend on:

* `dng05-Decker-3cf7cace.sav` — Temple start (archive `GAME1`); used by the
  walk / dungeon-view / char tests via slot 1.
* `dng00-Conan-d8b1cad7.sav` — party in front of **Cyldane** (OT-001 fixture);
  used by `tests/port_town_test.py` to pin the town-name selector.
* `dng05-Conan-e6c8c8bb.sav` — dungeon with wandering monsters (combat trigger).

`manifest.tsv` is regenerated by the ingest script; do not edit it by hand.

## Owner-supplied scenario saves (documented)

These are extra owner uploads, archived only (NOT installed into a slot, so they
can never clobber the slot fixtures above). Play one with
`cp saves/<file> game/GAMES/GAME6` or `lof --play auto --save saves/<file>`:

* `dng11-Grischnak-6378330c.sav` — **"Monastery of Sagacita"**, map **`DNG11`**,
  lead **Grischnak**. Party: Grischnak, Baldrek, Zork, Brynja, Draven, Eljot.
  Facing `E`, time-of-day 4 (Midday), morale 0. (uploaded 2026-11-25 as `GAME1`)
* `dng43-Joanna-85377b06.sav` — **"The Mines"**, map **`DNG43`**, lead **Joanna**.
  Party: Joanna, Skol, Elzndra, Merlin, Claudia, Dorgir. Facing `S`, time-of-day 6
  (Sunset), morale 0. (uploaded 2026-11-25 as `GAME5`)

Both map files (`game/DNGS/DNG11`, `game/DNGS/DNG43`) exist in the release, so the
port's `--play auto --save saves/<file>` renders them.  (The old "D8/D9 never
used" / "maps ≤ DNG13" notes predate these deeper two-digit maps.)

* `dng01-Joanna-f969c0ed.sav` — **"Monastery of Sagacita"** (entrance), map
  **`DNG01`**, lead **Joanna**. Party: Joanna, Skol, Elzndra, Merlin, Claudia,
  Dorgir. Facing `E`, time-of-day 1 (Dawn), morale 1. **Two high-level casters:**
  Joanna (prof 10, **lvl 12**, magic 17/18) and Skol (prof 5, **lvl 11**, magic
  14/14) — the rest are lvl 1–2. This is the **deepest / highest-level** fixture
  (the others are ≤ lvl 4).  Caveat (owner-supplied): both high-level members'
  XP (`+0x6c`) is a large value that is **negative signed** (`0xFFFF…`) because
  the owner levelled them via an out-of-combat-heal negative-XP quirk — so XP-gated
  features (House training threshold) behave oddly on these two, but their
  level/HP/magic/stat fields are what the stat-recompute tests need.  `GAME1`
  (`dng11-…`) is one dungeon level **deeper** than this entrance.
